# Driver application shell

The Driver app starts after the shared Identity foundation. DriverProfile, compliance eligibility and explicit vehicle/service permissions remain separate from account authentication.

Phase 0.6 extends the assignment-to-pickup client with low-distraction active telemetry, authoritative health/reconnect state, persistent SOS, destination-approach evidence and governed completion. Required handover is shown as a hard blocker. Navigation, production device capture and authorised handover entry remain future work.

Phase 0.7 reads separately posted DriverEarning truth. The client never infers an earning from Journey completion or Rider fare, and an earning never implies payout.
